# xlsx-tui 最小演示设计

## 目标

创建一个独立的 Rust 终端程序，用于试用大表格的终端编辑体验。它不替换、不修改现有的 `NumDesTools.XlsxEditor` WPF 项目，先作为 `tools/xlsx-tui/` 下的独立演示程序存在。

首版成功标准：用户可以从命令行打开真实 `.xlsx` 文件，切换多个 sheet，使用键盘和鼠标定位单元格，编辑一个值，保存后用 Excel 正常打开并看到修改结果。

## 明确边界

### 必须支持

- 打开命令行传入的 `.xlsx` 文件。
- 显示多个 worksheet，并支持 sheet 切换。
- 方向键和鼠标点击定位当前单元格。
- 鼠标滚轮和 PageUp/PageDown 浏览行。
- Enter 进入编辑，Enter 提交，Esc 取消。
- 支持普通文本、数字、空值编辑。
- Ctrl+S 保存到原文件，保存过程使用临时文件再原子替换，避免直接写坏原文件。
- 退出前处理未保存修改。
- 使用 UTF-8 文本和 Unicode 宽度计算，中文单元格不能造成布局错位。

### 暂不支持

- 排序、筛选、冻结窗格、整行整列选择。
- 撤销/重做。
- 多工作簿同时打开。
- 公式计算引擎。
- 样式编辑、合并单元格编辑、图表编辑、图片编辑、数据验证编辑。
- Ribbon 或 Excel-DNA 集成。

### 公式策略

首版不强制把公式转换为值。默认目标是保留已有公式；编辑公式单元格时，输入内容按用户输入保存，不在 TUI 内计算结果。

保存层 POC 必须验证以下行为：

- 未编辑的公式是否仍存在。
- 编辑普通单元格后，公式所在单元格的结果、公式文本和相关 XML 是否没有被意外清除。
- 如果候选保存库无法可靠保留公式，则不得静默接入；改用 ZIP/XML 定点写回，或明确将“公式转当前缓存值”作为后续经用户确认的策略。

## 技术方案

### 保存层先行验证

在接入 TUI 前，先对真实工作簿做保存层 POC：

1. 用候选库打开 `Item.xlsx` 的副本。
2. 修改一个普通字符串单元格。
3. 保存到临时输出文件。
4. 检查输出文件能否被 ZIP/XML 解析器读取。
5. 检查多个 sheet、公式、样式索引、合并单元格、列宽、图片和其它未编辑部件。
6. 使用 Excel 或可用的 OOXML 校验方式确认没有修复提示。

候选库优先验证 `umya-spreadsheet`。它是 MIT 许可、纯 Rust、支持已有 xlsx 读写和多 sheet。如果 POC 发现未编辑内容丢失，保存实现改为 ZIP 原始复制加 worksheet XML 定点补丁；不得用会静默丢格式的全量重建方案。

### TUI 技术栈

- `ratatui` 和 `crossterm`：沿用仓库现有 `lazykey`、`conflict-tui` 的技术路线。
- `calamine`：首选读取层，负责 worksheet 列表和单元格展示数据。
- `tui-textarea`：候选编辑输入控件；若与仓库当前 ratatui 版本不兼容，则使用小型自有输入缓冲，不升级整个现有 Rust TUI 生态。
- `arboard`：候选系统剪贴板；首版只在依赖兼容且实现成本低时接入，不为剪贴板阻塞核心编辑闭环。
- `unicode-width`：处理中文和宽字符显示宽度。

### 模块边界

```text
tools/xlsx-tui/
  src/main.rs       CLI 参数、错误出口、启动 TUI
  src/app.rs        workbook 状态、当前 sheet/行/列、dirty 状态、编辑状态
  src/io.rs         xlsx 读取、保存层适配、原子替换
  src/tui.rs        ratatui 布局、sheet 标签、网格、状态栏、帮助提示
  src/input.rs      键盘/鼠标事件转换为 AppAction
  src/editor.rs     当前单元格输入缓冲和提交/取消
```

数据模型只存演示需要的单元格文本和 worksheet 元数据。不要复制现有 C# `ColumnStore`，也不要在首版引入公式引擎或完整样式模型。

## 交互设计

```text
┌─ xlsx-tui · Item.xlsx ───────────────────────────────────────┐
│ [Sheet1]  Sheet2  Sheet3                                    │
├──────┬──────────┬──────────────┬──────────┬─────────────────┤
│ 行号 │ A        │ B            │ C        │ D               │
├──────┼──────────┼──────────────┼──────────┼─────────────────┤
│ 1    │ ...      │ ...          │ ...      │ ...             │
│ 2    │ ...      │ ▶ 当前单元格 │ ...      │ ...             │
│ 3    │ ...      │ ...          │ ...      │ ...             │
├───────────────────────────────────────────────────────────────┤
│ NORMAL · ↑↓←→移动 · Enter编辑 · Esc取消 · Ctrl+S保存 · q退出 │
└───────────────────────────────────────────────────────────────┘
```

- Normal：方向键移动，Tab/Shift+Tab 切换 sheet，鼠标点击定位，滚轮滚动。
- Insert：输入字符，Backspace 删除，Enter 提交，Esc 取消。
- Ctrl+S：保存当前工作簿并显示成功或失败状态。
- q/Esc：无修改时退出；有修改时显示保存、放弃、返回选项。
- `?`：显示一屏帮助，避免用户必须记忆快捷键。

网格只渲染当前终端视口内的行和列。列宽首版采用固定默认宽度并按终端宽度裁剪；水平滚动通过列偏移实现，不引入尚未验证兼容性的 `rat-ftable`。

## 错误处理

- 缺少输入路径、文件不存在、格式不支持：启动前输出简洁错误并返回非零退出码。
- 读取失败或 sheet 解析失败：不进入半初始化 TUI，输出具体 sheet/文件错误。
- 保存失败：保留 TUI 和 dirty 状态，显示错误，不覆盖原文件。
- 临时文件写入成功后才执行原子替换；替换失败时保留临时文件路径，便于恢复。
- 不捕获并吞掉错误；TUI 终端恢复必须通过 guard 或等价的清理路径完成。

## 测试与验收

### 单元测试

- A1 列名与行列坐标转换。
- 当前单元格边界移动不会越界。
- 编辑提交、取消和 dirty 状态转换。
- 鼠标坐标映射到可见行列。
- 中文、空值、XML 特殊字符的显示/保存输入。

### 保存层 POC 测试

- 修改普通字符串值后，输出可读取。
- 多 sheet 数量和名称不变。
- 未编辑单元格的样式索引、合并范围和列宽不变。
- 公式保留策略符合实际输出；不能静默丢公式。
- 原子保存失败时原文件仍可读取。

### 手工试用

使用真实 `C:\M1Work\public\Excels\Tables\Item.xlsx`：

1. 启动并切换至少两个 sheet。
2. 用键盘和鼠标定位不同区域。
3. 修改一个普通值并保存。
4. 用 Excel 打开文件，确认修改存在且没有修复提示。
5. 关闭后重新打开，确认修改仍存在。

## 后续扩展顺序

只有首版真实试用通过后，才考虑按收益增加：搜索、复制粘贴、撤销/重做、整行整列选择、排序筛选、冻结窗格。任何扩展都不应先假设完整替换 WPF 版。
